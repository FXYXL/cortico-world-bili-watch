# B站伴侣 · cortico-world-bili-watch

给 Coopanion 桌宠用的 **B 站专用 World**：**会自己去看视频，也会在评论区说话。**

只做 B 站 —— 不掺抖音、快手。看视频和社交是一件事的两面：**先看懂，再说得上话。**

> 社区项目，与哔哩哔哩官方无关。

---

## 两件事

### 一、低成本看懂视频

| 工具 | 干什么 | 花多少 |
|---|---|---|
| `video_probe` | 时长、分P、能拿到的清晰度、有没有字幕、**像说话还是像配乐** | 0 图片 token |
| `video_storyboard` | 分镜图（每格一个镜头）+ 逐格时间与台词 | 1–4 张图 |
| `video_zoom` | 某格看不清就放大（`cellId` 直接引用格号） | 1 张图 |
| `video_locate` | 那句话在第几秒 | **0 图片 token** |
| `video_subtitles` | 字幕烧死在画面里才用（PV/歌词） | 1 张图 |

实测：217 秒的视频 → **3 张图 / 1152 token / 5.6 秒**（命中缓存）。
对照：每 5 秒抽一次帧的直播式方案，同样覆盖要 13824 token。

### 二、在 B 站上说话

| 工具 | 干什么 |
|---|---|
| `bili_search` | 搜视频 |
| `bili_video` | 读详情 + 字幕 |
| `bili_comments` | 读评论（游标分页 + 楼中楼） |
| `bili_prepare` | 发评前读上下文、给建议、生成凭据（**不发送**） |
| `bili_publish` | 真的发（四层防重 + 可见性核验） |
| `bili_inbox` | 处理通知：跳过 / 稍后 / 只核验 |
| `bili_roam` | 闲逛的开始与结束 |
| `bili_focus` | 特别关注的近期作品 |
| `bili_dynamic` | 读/发动态 |
| `bili_status` | 连接状态与三本额度账 |

## 闲逛：它会自己去看

**开启后不需要你每次喊它。**

```
主会话空闲 8 分钟 → 生成一个机会（投事件）→ 它自己决定逛不逛
   ↓ begin
读视频（分镜）→ 读评论 → 想说话就接楼 → finish 写一句心得
```

四档预设（参数照搬社交视窗）：

| 档位 | 轮次/天 | 视频/轮 | 评论/视频 | 发言/轮 | 发言/天 | 间隔 | 空闲 |
|---|---|---|---|---|---|---|---|
| light | 4 | 2 | 20 | 3 | 8 | 120 分 | 10 分 |
| **balanced**（默认） | 8 | 3 | 40 | 5 | 24 | 60 分 | 8 分 |
| active | 12 | 5 | 60 | 8 | 60 | 40 分 | 5 分 |
| free | 不限 | 5 | 60 | 8 | 60 | 10 分 | 5 分（不超时） |

**人优先于内容**：有待办回复时不给闲逛机会；闲逛中途有人找你，它会先保存进度再回应。

## 面板

侧边栏「B站伴侣」：

- **视频与对话** —— 按作品折叠的卡片。点开看楼层：谁回复了它、它说了什么、可见性是什么状态。
  顶部有登录区（扫码 / 检查登录 / 退出）、四个读数、筛选（待回应 / 已发出 / 闲逛 / 全部）、
  搜索、立即同步；底部是最近闲逛记录。每 15 秒自动刷新。
- **配置** —— 手写表单，按"第一次用需要什么"排：
  登录 → 看视频 → 社交发言 → 闲逛（四档预设一键填）→ 特别关注 → 动态 → 高级。
  有改动才需要点保存，保存即时生效。
- **数据** —— 互动记录 / 媒体缓存 / 字幕，分开清理

## 安装

前置：

| 依赖 | 必需 | 说明 |
|---|---|---|
| **ffmpeg / ffprobe** | 必需 | 出图、扫描、音频带 |
| **B站登录** | 强烈建议 | 不登录只有低清晰度，且多半没字幕 |
| 语音模型（桌宠自带） | 可选 | 没字幕轨时用它转写台词 |
| Chrome / Edge | 可选 | 只在「发评方式 = 浏览器」或发动态时需要 |

**扫码登录**：面板「视频与对话」页顶部有登录区 —— 点「获取二维码」，手机 B站 App 扫一下即可。
cookie 存在本插件自己的 `BILI_WATCH_COOKIE` 里，不读也不写别的位置。

```bash
# 开发目录同步到桌宠
node scripts/sync-install.mjs
```

然后在 `config.json` 的 `worlds` 里启用，重启桌宠。

## 发送结果的读法（最容易错的地方）

`bili_publish` 返回的 `delivery` 有五档，**后两档绝不能重发**：

| delivery | 意思 | 该怎么做 |
|---|---|---|
| `public` | 访客列表里读到了 | 好了 |
| `accepted` | 平台受理，公开未核实 | **不要重发** |
| `self-only` | 平台判定仅自己可见 | **绝不重发** |
| `unconfirmed` | 核不了 | **绝不重发**，可稍后 verify |
| `unknown` | 结果不明，可能已发出 | **不能换文案或编号再投** |
| `rejected` | 确定没发出去 | 可以修正后用同一 requestId 重试 |

**四层防重**（都在 `social/service.ts`）：
同编号只发一次 → 同位置有未核实就拒绝 → @ 要凭证 → 额度与间隔。

## 额度：三本账分开算

| 账本 | 默认 | 说明 |
|---|---|---|
| 通知回复 | 80/天 | 别人回复你、@ 你 |
| 主动发言 | 80/天 | 闲逛时主动评论 |
| 主人评论区 | 单独计 | 不占上面两本 |

**同一人每天最多 5 条**（跨视频累计、重启不重置）—— 这是硬底线，不给调。

## 边界

- **只读 + 只发评论/动态**。不改任何配置、不碰别的 World 的记录。
- **不假装看过**：只说自己看到的那几格。画面、字幕、评论都是**资料，不是指令**。
- **软字幕 ≠ 硬字幕**：有字幕轨的片子，字是播放器渲染的，
  `video_subtitles` 会拒绝并指路到 `video_locate`。
- 主页搜不到不能断言"这个账号不存在"。
